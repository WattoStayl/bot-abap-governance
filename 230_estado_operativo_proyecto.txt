ESTADO
El experimento de Agent Builder con gobernanza pública en GitHub/GitHub Pages permanece PAUSADO por instrucción humana. La publicación puede permanecer disponible y la indexación pública puede continuar, pero no se realizarán nuevas acciones sobre ese experimento hasta decidir retomarlo.

La gobernanza pública sigue siendo exclusivamente experimental. No está autorizado almacenar operación real o confidencial aquí.

El diseño del experimento de canon local portátil queda VALIDADO y entra en una campaña de prueba operativa sintética desde cero. Su definición vigente está en `116_experimento_canon_local_portable.md`.

La configuración de referencia para la campaña es BotConsultor v8 de pruebas, derivada de la v7 simplificada. La Description breve se mantiene sin cambios. La v8 incorpora como controles explícitos los hallazgos de preprueba ya observados:
- una solución definida, aceptada o recomendada no equivale a ejecución realizada;
- DISEÑO no sustituye DESARROLLO/EJECUCIÓN en el Checklist Global; debe existir ejecución aplicable o justificación de NO APLICA;
- `LISTO PARA VALIDACIÓN` significa que el Checklist Global puede certificarse directamente mediante `CHECKLIST: CERTIFICADO`, sin gates adicionales;
- el porcentaje Global se calcula exclusivamente desde los puntos superiores del Checklist Global certificado; el Checklist Operativo no redefine su denominador;
- el cierre de un punto Global y el 100 % deben consolidar y entregar automáticamente el `.md`; si la plataforma no permite adjuntarlo, el agente debe declararlo y usar Markdown como alternativa sin afirmar que creó un archivo.

PROTOCOLO DE CAMPAÑA
La prueba se ejecutará secuencialmente, un caso de uso a la vez y preferentemente en chats nuevos para evitar contaminación de contexto entre configuraciones o casos.

Para cada caso CUx:
1. la lista de correcciones comienza vacía;
2. el evaluador entrega un único prompt de prueba al humano;
3. el humano lo transmite a BotConsultor y devuelve la respuesta observada;
4. el evaluador compara respuesta observada contra comportamiento esperado;
5. si existe desviación, se registra una corrección `CUx-Cnn` con magnitud/impacto, causa probable y propuesta de corrección en un párrafo;
6. las correcciones se acumulan sin perder las anteriores durante todo el caso;
7. si una respuesta cumple lo esperado, se muestra únicamente la lista acumulada y se entrega el siguiente prompt;
8. al terminar el caso, el humano guarda la lista; luego se limpia antes de iniciar el siguiente caso.
